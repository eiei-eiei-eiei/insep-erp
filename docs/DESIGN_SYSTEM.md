# Design system — "เหล็กกล้า" (Steel)

> ตัดสินใจ 2026-08-01 (D43) · ทิศทางเลือกจากตัวอย่าง 3 แบบ → "ห้องคุม" · ชุดสี → "เหล็กกล้า"
> **ไฟล์นี้คือกติกาฝั่ง UI เทียบเท่ากติกาเหล็กฝั่งสูตรใน CLAUDE.md — อ่านก่อนแตะหน้าตาแอปทุกครั้ง**

## หลักการ 3 ข้อ

1. **ห้ามเขียนสีตรง ๆ ใน component** — ไม่มี `bg-slate-800`, `text-red-500`, `#2563eb` ในไฟล์ `.tsx` อีก
   ใช้ token เท่านั้น (ดูตารางด้านล่าง) · ถ้าไม่มี token ที่ต้องการ = เพิ่ม token ไม่ใช่ hardcode
2. **สีแบรนด์เปลี่ยนตามลูกค้าได้ · สีสถานะล็อกตายทุกราย**
   เพราะ "เหลือง = มีของค้าง" ต้องแปลเหมือนกันทุกโรง เวลาสอนงาน/แก้ปัญหาทางโทรศัพท์
3. **โหมดมืดไม่ใช่การกลับสี** — เป็นค่าคนละชุดที่ปรับ contrast มาแล้ว
   (เช่น เขียว `#17754b` บนพื้นขาว ↔ `#4fb07c` บนพื้นดำ · ตัวหนังสือโหมดมืดไม่ใช่ขาวล้วน กันล้าตา)

## ทำไมเลือก "เหล็กกล้า"

โจทย์คือ **ขายให้โรงเหล้าหลายเจ้า** การไม่มีสีแบรนด์ตายตัวจึงเป็นข้อได้เปรียบ:
UI พื้นฐานเป็นเทาล้วน → สีแบรนด์แตะแค่ **4 จุด** (ปุ่มหลัก · แท็บที่เลือก · วงชื่อผู้ใช้ · แท่งกราฟชุดหลัก)
เปลี่ยนสีให้ลูกค้า = เปลี่ยนค่าเดียว ไม่ต้องไล่ปรับทั้งแอป และทำโหมดสว่างได้ง่ายที่สุด

## Token (นิยามจริงอยู่ใน `app/globals.css`)

### พื้นผิว
| token | ใช้กับ |
|---|---|
| `bg-page` | พื้นหลังหน้า (นอกการ์ด) |
| `bg-card` | การ์ด/กล่องเนื้อหา |
| `bg-nav` | แถบนำทาง · แถบสรุปยอดล่างจอ |
| `bg-input` | ช่องกรอก — **จมกว่าการ์ด** เพื่อให้รู้ว่าพิมพ์ได้ |
| `bg-raised` | หัวตาราง · hover · แถบที่ยกขึ้นเล็กน้อย |
| `bg-overlay/50` | ฉากหลัง modal (ใช้ผ่าน `<Modal>` เท่านั้น) — **ห้ามใช้ `bg-ink`** (โหมดมืด ink เป็นสีอ่อน ฉากจะสว่าง) |

### เส้น / ตัวอักษร
| token | ใช้กับ |
|---|---|
| `border-line` | เส้นขอบหลัก (การ์ด/ช่องกรอก/ปุ่ม) |
| `border-line-soft` | เส้นคั่นแถวในตาราง |
| `text-ink` | ข้อความหลัก · ตัวเลขเงิน |
| `text-muted` | ข้อความรอง · คำอธิบาย |
| `text-faint` | ป้ายกำกับ · หน่วย · ข้อความประกอบ |

### สถานะ — **ล็อกตาย ห้ามให้ลูกค้าเปลี่ยน**
| ความหมาย | token | ใช้เมื่อ |
|---|---|---|
| ปกติ/สำเร็จ | `text-ok` `bg-ok-bg` `border-ok-line` | ปิด batch แล้ว · บันทึกสำเร็จ · ชำระครบ |
| ค้าง/รอดำเนินการ | `text-warn` `bg-warn-bg` `border-warn-line` | หม้อยังไม่จบ · รอคลังแพ็ค · ยังไม่ได้สร้างรายงาน |
| ผิดพลาด/เกินกำหนด | `text-crit` `bg-crit-bg` `border-crit-line` | error · เกินกำหนดชำระ · ปุ่มยกเลิก/ลบ |

### แบรนด์ — เปลี่ยนตามลูกค้าได้
| token | ใช้กับ |
|---|---|
| `bg-brand` + `text-on-brand` | ปุ่มหลัก (สิ่งที่ผู้ใช้ควรทำต่อ) — **คู่กันเสมอ** |
| `text-brand` | ลิงก์ · แท็บที่เลือกอยู่ · ตัวเลขที่ต้องเน้น |
| `bg-brand-soft` | พื้นแท็บที่เลือก · วงชื่อผู้ใช้ (คำนวณจาก `color-mix` 12%) |
| `border-brand-line` | เส้นขอบของสิ่งที่ผูกกับแบรนด์ (32%) |

⚠️ **พื้นหลัง/การ์ดเป็นสีกลางเสมอ ไม่เปลี่ยนตามแบรนด์** — สีแบรนด์เป็น "สีเน้น" ไม่ใช่ "สีพื้น"
ผลข้างเคียงที่ผู้ใช้เจอจริงตอนเทส (2026-08-12): หน้า `/login` มีของที่ใช้สีแบรนด์แค่ปุ่มกับกล่อง
ตัวอักษรแรก → **ดูเหมือนสีไม่เปลี่ยนเลยทั้งที่ระบบทำงานถูก** → เพิ่มแถบสีแบรนด์ `h-2` บนหัวการ์ด
(`app/(auth)/login/LoginForm.tsx`) · ขึ้นเฉพาะตอนมี subdomain — ไม่มี subdomain ต้องเหมือนเดิมเป๊ะ
**บทเรียน**: หน้าที่มี element น้อย ต้องจงใจใส่จุดสีแบรนด์ให้เห็น ไม่งั้นลูกค้าจะคิดว่า white-label ไม่ทำงาน

### กราฟ
`chartColor(i)` จาก `lib/shared/chart.ts` (8 สีวนซ้ำ) · `CHART_GRID` `CHART_LABEL` `CHART_AXIS_LABEL`
**กติกา**: กราฟชุดหลักใช้สีแบรนด์ · ชุดรองใช้ `--color-series` (เทา) · **ห้ามใช้เขียว/แดง** ในกราฟ
เพราะสองสีนั้นสงวนให้สถานะ — ไม่งั้นแท่ง "รายจ่าย" สีแดงจะอ่านเหมือน "มีข้อผิดพลาด"

## ระดับของปุ่ม (3 ระดับ ไม่ใช่ 7 สี)

| ระดับ | หน้าตา | ใช้เมื่อ |
|---|---|---|
| primary | `bg-brand text-on-brand` | สิ่งที่ควรทำต่อในหน้านั้น — **มีได้ 1 อันต่อกลุ่ม** |
| secondary | `border-line bg-card text-muted` | ทำได้ ไม่เร่ง (พิมพ์ · แก้ไข · ดูรายละเอียด) |
| danger | `border-crit-line text-crit` | ทำลาย/ย้อนกลับไม่ได้ (ยกเลิก · ลบ) — **แยกระยะจากปุ่มอื่น** |

component พร้อมใช้: `SaveButton` `RowBtn` `IconBtn` `Badge` ใน `lib/shared/ui.tsx`

## ไอคอน

ใช้ `lib/shared/icons.tsx` (SVG เส้น สืบสีจาก `currentColor`) — **ห้ามใช้อิโมจิเป็นปุ่ม/ไอคอน**
เหตุผล: อิโมจิเปลี่ยนหน้าตาตาม OS, ปรับสี/ขนาดไม่ได้, และตอนเดโมขายจะดู "ทำเล่น"
*(อิโมจิในข้อความอธิบาย เช่น "⚠️ กิจการนี้ยังไม่มีเลขสรรพสามิต" ยังใช้ได้ — อ่านเป็นเครื่องหมายวรรคตอน)*

## ตาราง

ทุกตารางใช้ `<table className="tbl">` — สไตล์อยู่ใน `globals.css` **layer `components`**
จึงเป็นแค่ "ค่าเริ่มต้น" · utility class ที่ใส่ราย `th`/`td` ยังทับได้เสมอ

```tsx
<TableWrap minWidth={620}>
  <table className="tbl">
    <thead><tr><th>วันที่</th><th className="num">ยอด</th></tr></thead>
    <tbody>
      <tr><td>01/08/69</td><td className="num">1,240.00</td></tr>
      <tr className="editing">…</tr>   {/* แถวที่กำลังแก้ inline */}
    </tbody>
  </table>
</TableWrap>
```

| คลาส | ผล |
|---|---|
| `.tbl` | หัวตารางตัวพิมพ์ใหญ่/เล็ก/muted · เส้นคั่นแถว · padding · hover |
| `td.num` / `th.num` | ชิดขวา + `tabular-nums` + ไม่ตัดบรรทัด |
| `td.act` | ช่องปุ่มท้ายแถว (ชิดขวา ไม่ตัดบรรทัด) |
| `tr.editing` | แถวที่กำลังแก้ inline (พื้นสีเตือน) |

**ห้ามใส่ `p-1` / `px-2 py-1` / `text-left` ราย cell อีก** — `.tbl` คุมให้แล้ว
ใส่ได้เฉพาะที่เป็นข้อยกเว้นจริง: ความกว้าง (`w-32`), สี (`text-crit`), `whitespace-nowrap`

## จอมือถือ — ห้ามมีอะไรกว้างเกินจอ (D165)

ผู้ใช้เปิดบนมือถือแนวตั้ง (จอ 360px · แคบสุดที่ต้องรองรับ 320px) — ของที่กว้างกว่าจอต้อง **เลื่อนได้ในกรอบของมันเอง** ไม่ใช่ดันทั้งหน้า

1. **ทุก `<table>` ต้องอยู่ในกรอบเลื่อน** — `<TableWrap>` หรือ `<div className="overflow-x-auto">` (ตาราง 2 คอลัมน์ก็ห่อ — ถูกกว่ามาไล่ทีหลัง)
2. **`grid` ที่เป็น layout หน้า ต้องบอก `grid-cols-1` บนจอเล็ก** และคอลัมน์ยืดใช้ **`minmax(0,1fr)` ไม่ใช่ `1fr`**
   🪤 `grid` เปล่า / `1fr` = "กว้างอย่างน้อยเท่าของข้างใน" → คอลัมน์ขยายตามตาราง แล้ว **กรอบ overflow-x-auto ข้างในไม่ทำงาน** (ตัวแก้งวดใบเสนอราคาดันหน้าเป็น 450px บนจอ 360px ทั้งที่มีกรอบเลื่อนห่ออยู่แล้ว)
3. **ข้อความยาวที่อยู่ในแถว flex** (ชื่อแบรนด์ · ชื่อลูกค้า) ใส่ `min-w-0` ที่ตัวห่อ + `truncate` ที่ข้อความ · ปุ่มข้าง ๆ ใส่ `shrink-0`
4. 🚨 **ห้ามแก้ด้วย `overflow-x: hidden` ที่ html/body** — ซ่อนของที่ล้นทิ้ง (ผู้ใช้เลื่อนไปดูไม่ได้) และทำให้ `position: sticky` ทั้งแอปไม่ติด

`lib/shared/mobileOverflow.test.ts` อ่านซอร์สล็อกข้อ 1, 2, 4 ไว้ · วิธีวัดในเบราว์เซอร์ (ยัดกล่องกว้างเข้าทุกกรอบเลื่อน) อยู่ใน `docs/TESTING.md` ส่วนที่ 120

## ตัวเลข

ยอดเงิน/ดีกรี/ปริมาณ ใส่คลาส `tnum` (tabular-nums) และชิดขวา → **หลักหน่วยตรงกันทุกแถว** กวาดตาเทียบได้เร็ว
`NumInput` / `NumBox` ทำให้แล้วอัตโนมัติ

## Touch target / จอสัมผัส (D173 เฟส 3)

ปุ่มในลิสต์/ตาราง: `min-h-[44px]` บนจอเล็ก แล้วยุบเป็นขนาดปกติที่ `sm:` ขึ้นไป (`RowBtn` ทำให้แล้ว)
หน้าที่ใช้นอกสถานที่ (จัดการออเดอร์ · คลัง) ห้ามต่ำกว่านี้

| เรื่อง | กติกา |
|---|---|
| ปุ่มทุกตัวบนอุปกรณ์ที่ใช้นิ้ว | สูง/กว้างอย่างน้อย **32px** อัตโนมัติ (`globals.css` · `@media (pointer: coarse)` ใน `@layer base`) — จอคอมไม่เปลี่ยน · คลาส `min-h-*` ยังทับได้ |
| ขยายพื้นที่แตะด้วย `::after` แบบ global | 🚨 ห้าม — ล้นกรอบ `overflow-x-auto` แล้วแถบแท็บ/ตารางเลื่อนขึ้นลงได้ |
| `title=` | จอสัมผัสไม่มีเมาส์ชี้ · `<TouchTitles />` (ใน layout) ทำให้ **แตะป้ายที่มี title แล้วเห็นข้อความ** — เฉพาะของที่ไม่ใช่ปุ่ม/ลิงก์/ช่องกรอก |
| เหตุผลที่ปุ่มเทา | 🚨 ต้องอยู่ **บนจอ** (`<MissingHint>` / บรรทัดใต้ปุ่ม) — ปุ่ม `disabled` ไม่ส่ง click จึงโชว์ title ให้ไม่ได้ |
| คำอธิบายใหม่ | ใช้ `<Help>` ไม่ใช่ `title=` |
| ป๊อปอัพ | `<Modal>` เท่านั้น — กล่อง `fixed inset-0 flex justify-center` ที่เนื้อหากว้างกว่าจอจะ **ถูกตัดด้านซ้ายและเลื่อนไปดูไม่ได้** (อาการที่ผู้ใช้เจอก่อนเฟส 1b) |

## แบรนด์ต่อลูกค้า (white-label)

ค่าอยู่ใน `app_settings` ของแต่ละ tenant (migration 0022) — **deploy โค้ดใหม่ไม่กระทบ**
เพราะโค้ดอยู่ที่ Vercel ส่วนค่าอยู่ที่ Supabase ของลูกค้า คนละที่กัน

| kind | ค่า |
|---|---|
| `brand_name` | ชื่อที่แสดงบนแถบเมนู |
| `brand_color` | ชื่อชุดสี (`steel`/`copper`/`green`/`indigo`/`wine`/`teal`/`rust`) — **ไม่ใช่รหัสสี** |
| `logo_url` | ลิงก์โลโก้ (ว่าง = ใช้ตัวอักษรแรกของชื่อ) |
| `default_mode` | `light` / `dark` (โหมดตอนเปิดครั้งแรก) |

แก้ได้จากแอป: **บัญชี → แท็บตั้งค่า → การ์ด "แบรนด์ของกิจการ"**

**ทำไมเก็บชื่อชุดสีไม่ใช่รหัสสี**: แต่ละชุดมีค่าคู่ สว่าง/มืด ที่ตรวจ contrast แล้ว
ถ้าให้กรอก hex เอง ลูกค้าเลือกเหลืองมะนาว → ตัวหนังสือบนปุ่มอ่านไม่ออก → กลายเป็นงานซัพพอร์ต

**เพิ่มสีใหม่**: เพิ่ม 2 บล็อกใน `globals.css` (สว่าง/มืด) + 1 แถวใน `BRAND_COLORS` (`lib/shared/branding.ts`)
+ แก้ CHECK constraint ใน migration ใหม่ · เฉดอ่อน/เส้นขอบคำนวณเองด้วย `color-mix`

⚠️ **กับดักที่เคยเจอ**: `data-mode` อยู่บน `<html>` (อ่านจาก cookie ฝั่ง server) แต่ `data-brand`
อยู่บน div ใน `(app)/layout.tsx` (กว่าจะรู้แบรนด์ต้อง login ก่อน) → selector ต้องเขียน
ทั้ง `[data-mode="dark"] [data-brand="x"]` (ลูกหลาน) และ `[data-mode="dark"][data-brand="x"]` (ธาตุเดียวกัน)

```tsx
<Modal title="เพิ่มคู่ค้า" onClose={close} onSubmit={save} busy={pending}
       footer={<><ModalCancel onClick={close} /><SaveButton pending={pending} onClick={save} /></>}>
  …ช่องกรอก…
</Modal>
```

| สิ่งที่ได้มาเอง | หมายเหตุสำหรับคนย้าย |
|---|---|
| เปิดแล้วเคอร์เซอร์อยู่ช่องกรอกแรก | อยากให้เริ่มช่องอื่น ใส่ `data-autofocus` ที่ช่องนั้น (`Combobox` ใช้ prop `autoFocus`) · จอสัมผัสไม่โฟกัสช่อง (กันคีย์บอร์ดเด้ง) |
| Enter ในช่องบรรทัดเดียว = `onSubmit` · Ctrl+Enter จากทุกที่ | ช่องที่ Enter มีความหมายของตัวเอง (เพิ่มแถว/เพิ่ม chip) ใส่ `data-enter="own"` ที่ช่องหรือกล่องที่ครอบ |
| Esc ปิดเฉพาะชั้นบนสุด · Tab วนในป๊อปอัพ · ปิดแล้วคืนโฟกัส | ลบ `<EscToClose>` กับ `onMouseDown` พื้นหลังของเดิมออก |
| ล็อกหน้าหลัง · เนื้อหายาวเลื่อนในฉาก · มือถือเป็นแผ่นติดขอบล่าง | ลบ `max-h-[..vh] overflow-y-auto` ที่เคยใส่กันล้น |
| ขนาด `size`: sm (384) · md (512 · ปริยาย) · lg (672) · xl (896) | เทียบจาก `max-w-*` เดิม |
| กดพื้นหลัง = ปิด | ฟอร์มยาว / รับเงิน / ออกเอกสาร ที่กดพลาดแล้วของหาย ใส่ `backdropClose={false}` (Esc กับ ✕ ยังปิดได้) |
| เนื้อหาโหลดทีหลัง → วางเคอร์เซอร์ให้เมื่อช่องกรอกโผล่ | ไม่ต้องทำอะไร |
| ปุ่มที่กดในป๊อปอัพไม่ไหลไปถึงคีย์ลัดของหน้าหลัง | ไม่ต้องทำอะไร |

🚨 **`onSubmit` (Enter = บันทึก) ใส่เฉพาะฟอร์มบันทึกธรรมดา** — ป๊อปอัพที่ยกเลิก / ออกเอกสารมีเลข / รับ-จ่ายเงิน / ตัดสต็อก / ปิดบิล / รีเซ็ตรหัส **ห้ามใส่** ต้องกดปุ่มเอง (เทสล็อก 9 ไฟล์ใน `keyboard.test.ts`)
ปุ่มลบในท้ายป๊อปอัพใส่ `mr-auto` ให้ไปชิดซ้าย ห่างจากปุ่มบันทึก

- ฉากหลังเป็น `bg-overlay/50` ที่เดียว (เดิมมี 5 ความเข้ม รวม `bg-black/60`)
- ปุ่มท้าย: ปุ่มรอง (`ModalCancel`) อยู่ซ้าย ปุ่มหลักอยู่ขวาสุด
- กติกาคีย์บอร์ดอยู่ที่ `lib/shared/keyboard.ts` (มีเทส) — component ทำตามผล ห้ามตัดสินเองใน component

## คำอธิบาย ⓘ — ใช้ `<Help>` ตัวเดียว (D173 เฟส 2)

ผู้ใช้สั่ง: โน้ตอธิบายที่วางเรียงตามหน้าจอทำให้รก → ย้ายเข้าปุ่มวงกลม กดแล้วค่อยเห็น

```tsx
<Card title="หมวดรายจ่าย" help="คำอธิบายของการ์ด">      // ⓘ ข้างหัวการ์ด
<Field label="วันครบกำหนด" help="คำอธิบายของช่อง">       // ⓘ ข้างป้ายช่อง
<Help>คำอธิบายที่ไม่ได้ผูกกับการ์ด/ช่อง</Help>            // วางข้างหัวข้อ/หัวคอลัมน์/ปุ่มที่มันอธิบาย
<Help tone="warn">ข้อควรระวัง</Help>                     // ! สีเหลือง
```

ตัวกลางทำให้เอง: กด/แตะ/Enter เปิด-ปิด · Esc ปิด (ไม่ปิดป๊อปอัพที่ครอบ) · กดที่อื่น/เลื่อนจอ ปิด · กล่องไม่ถูกตารางตัดและไม่ล้นจอมือถือ · อยู่ใน `<label>` ได้

### อะไรย้ายเข้า ⓘ ได้ — ต้องผ่าน **ทั้ง 3 ข้อ**

1. เป็น **คำอธิบาย** ว่าช่อง/การ์ด/ปุ่มนี้คืออะไร ทำงานยังไง มีไว้ทำไม ตัวอย่างการกรอก
2. ข้อความ **เหมือนเดิมทุกครั้ง** ไม่ขึ้นกับข้อมูล/สถานะ (ไม่ได้อยู่ใต้เงื่อนไข `{x && …}` ที่ผูกกับข้อมูล)
3. คนที่ **ไม่อ่านก็ยังทำงานถูก** — ไม่อ่านแล้วไม่เสียเงิน ไม่ยื่นเอกสารผิด ไม่ทำข้อมูลหาย

### อะไร **ต้องอยู่บนจอ** ห้ามย้าย

| ประเภท | ตัวอย่าง |
|---|---|
| คำเตือนเรื่องเงิน · ภาษี · เอกสารราชการ · สต็อก · ลบ/ย้อนไม่ได้ | สีเหลือง/แดง · ขึ้นต้น 🚨 ⚠ · "ยกเลิกแล้วใบกำกับ…" · "ขนาดขวดเกิน 5 ล." |
| ข้อความตามสถานะ | `<MissingHint>` · "ยังไม่ได้ตั้ง — ระบบใช้…" · "ยังไม่ได้บันทึก" · เหตุผลที่ปุ่มเทา · ผลการกรอง "ซ่อนอยู่ 3 รายการ" |
| หน้าจอว่าง + บอกว่าทำอะไรต่อ | "— ยังไม่มีรายการ —" · "กด เพิ่ม เพื่อเริ่ม" |
| **ข้อมูล** ไม่ใช่คำอธิบาย | สูตรของแถว · หน่วย · จำนวน · วันที่ · "(ปิดอยู่)" · ยอดที่บันทึกไว้ · ตัวอย่างสด (preview) |
| ส่วนของป้าย สั้น ๆ | "(ไม่บังคับ)" · "บาท" · "ต่อเดือน" |
| ข้อความยินยอม/กฎหมาย | ช่องยินยอม PDPA · ข้อความในกล่องยืนยัน (`useConfirm`) |
| หน้าก่อนล็อกอิน · หน้าถูกระงับ · error | `(auth)` ทั้งโฟลเดอร์ · `error.tsx` |
| เอกสารที่พิมพ์ | ทุกอย่างใน `print.ts` · `reportHtml.ts` · `lib/pdf` · `receipt.ts` |

**ไม่แน่ใจ = คงไว้บนจอ** (ย้ายผิด = ผู้ใช้ไม่เห็นคำเตือน · คงไว้ผิด = รกขึ้นนิดเดียว)

### วิธีย้าย

- **ห้ามแก้ถ้อยคำ** — ยกข้อความเดิมไปทั้งก้อน (ตัดได้แค่ ★ / "หมายเหตุ:" นำหน้า) · `<b>` / `<br/>` ข้างในเก็บไว้
- โน้ตใต้การ์ด/ใต้หัวการ์ด → `help=` ของ `<Card>` · โน้ตใต้ช่อง → `help=` ของ `<Field>` · ที่อื่น → `<Help>` ข้างหัวข้อที่มันอธิบาย
- โน้ตเดียวมีทั้งคำอธิบายและคำเตือนปนกัน → **แยก**: ส่วนคำอธิบายเข้า ⓘ ส่วนคำเตือนอยู่บนจอ · แยกไม่ออก = คงทั้งก้อน
- `tone="warn"` (!) ใช้กับข้อควรระวังที่ผ่านข้อ 2-3 แต่ควรสะดุดตากว่าคำอธิบายทั่วไป เช่น "มีผลกับงวดถัดไปเท่านั้น" · ถ้าไม่ผ่านข้อ 3 ห้ามใช้ — ต้องอยู่บนจอ
- ห้ามใช้ `title=` เป็นที่เก็บคำอธิบายใหม่ (จอสัมผัสมองไม่เห็น) · ห้ามเขียนปุ่ม ⓘ เอง (เทส `help.test.ts`)
- ⓘ 1 การ์ดไม่ควรเกิน ~3 ปุ่ม — เกินกว่านั้นแปลว่าการ์ดต้องการคำอธิบายรวมที่หัวการ์ดอันเดียว

## ตัวอักษร 3 ระดับต้องอ่านออกทุกพื้นผิว (D173)

`text-ink` / `text-muted` / `text-faint` ต้องได้คอนทราสต์ ≥ 4.5:1 บน page/card/nav/input/raised ทั้งสองโหมด
— `lib/shared/contrast.test.ts` อ่านค่าจาก `globals.css` มาคิดทุกคู่ · ปรับสีแล้วจางลง = เทสแดง
**ห้ามทำให้จางด้วย `opacity-*` หรือ `text-ink/50`** (ความโปร่งใสคูณกับพื้นหลัง ผลต่างกันทุกพื้นผิว) ใช้ระดับถัดไปแทน

## หน้าตั้งค่า — เมนูข้าง + รายการเป็นแถว (D173 · ผู้ใช้เลือกแบบ ก)

ใช้กับทุกหน้าที่เป็น "รายการค่าตั้ง" (หมวดหมู่ · อัตรา WHT · คู่ค้า · บัญชีเงิน · ตั้งค่าของ บาร์/เงินเดือน/ตั้งค่ากลาง)

1. **เมนูข้างซ้าย** แสดงหัวข้อย่อยของหน้านั้น · เห็นทีละเรื่อง · จอเล็กกว่า `md` ยุบเป็นดร็อปดาวน์บนสุด (ห้ามเป็นแถบเลื่อนแนวนอน)
2. **หัวการ์ด**: ชื่อเรื่อง + ปุ่ม ⓘ + จำนวนรายการชิดขวา
3. **1 รายการ = 1 แถว** ชื่อชิดซ้าย · ไอคอน แก้/ลบ ชิดขวา (`IconBtn`) · **เลิกใช้ chip กับ ✕ และลิงก์ตัวหนังสือ "แก้ไข/ลบ"**
4. **แถวสุดท้ายเป็นช่องเพิ่ม** พิมพ์แล้วกด Enter = เพิ่ม · เคอร์เซอร์อยู่ช่องเดิมพร้อมพิมพ์ต่อ
5. แก้ชื่อ = แก้ในแถว (Enter บันทึก · Esc เลิก) · ลบ = ถามผ่าน `useConfirm`
6. คำอธิบายว่าเรื่องนี้คืออะไร → อยู่ใน ⓘ · **คำเตือนเรื่องเงิน/ภาษี/เอกสารราชการยังแสดงตลอด** ไม่ย้ายเข้า ⓘ
