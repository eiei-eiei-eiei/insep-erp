## ส่วนที่ 3 — คีย์เองครบ flow ด้วย "ยินทดสอบ" (ชุด B)

> ทำในแท็บของ 🏭 ผลิต ทีละสเต็ป — จบแล้ว "ยินทดสอบ" จะมีสต็อกขวด

### 3.1 บันทึกวัตถุดิบรับ
แท็บ **วัตถุดิบ** → ประเภท **รับ** · วัตถุดิบ **น้ำตาลทดสอบ** · จำนวน **50** → บันทึก
→ เขียว ✅

### 3.2 ลงหมัก
แท็บ **ลงหมัก** → ชื่อสุรา **ยินทดสอบ** · (Batch เติมอัตโนมัติเป็นเลขถัดไป เช่น `3/69` เพราะ seed ใช้ `1/69`, `2/69` แล้ว) · ภาชนะ **ถังหมักทดสอบ** จำนวน **1**
→ วัตถุดิบหลัก: **น้ำตาลทดสอบ** จำนวน **30** → กด **ลงหมัก**
→ เขียว ✅ · ไปแท็บ **วัตถุดิบ**… (ระบบเบิก "จ่าย" น้ำตาล 30 อัตโนมัติแล้ว — จะเห็นในรายงานภายหลัง)

### 3.3 ติดตามหมัก
แท็บ **ติดตามหมัก** → เลือก batch ที่เพิ่งสร้าง → กรอก pH 4.2 / Brix 12 / อุณหภูมิ 30 → บันทึก ✅
→ บันทึกซ้ำอีก 2-3 ครั้ง (เปลี่ยนค่าเล็กน้อย) → **การ์ด "กราฟแนวโน้มการหมัก" ขึ้นเส้น pH/Brix/°C + ตารางประวัติ** ✅

### 3.4 กลั่น (จุดที่ใช้สูตร ABV@20 + ปิด batch)
แท็บ **กลั่น** → เลือก batch → กด **+ เริ่มหม้อใหม่** (ขึ้น "กำลังกลั่นหม้อที่ 1")
- บันทึก reading: ช่วง **กลาง** · นาทีที่ **10** · ดีกรีที่อ่าน **80** · อุณหภูมิสุรา **30** → ช่อง **ดีกรี@20°C (คำนวณ)** ต้องขึ้นเลขอัตโนมัติ (≈ 78.xx) · อุณหภูมิไอ **95** · ปริมาณสะสม **10** → บันทึกค่า ✅
- บันทึกอีก 1-2 reading (เปลี่ยนนาที/ค่า) → **การ์ด "กราฟการกลั่น" ขึ้นเส้น ดีกรี@20 + อุณหภูมิไอ** ✅
- บันทึกอีก 1 reading: ช่วง **จบหม้อ** · ดีกรีที่อ่าน **80** · อุณหภูมิ **30** · ปริมาณสะสม **10** → บันทึกค่า
- เลื่อนลงการ์ด **ปิด Batch** → กด **ใช้ค่าสรุป** (เติมปริมาณ 10.000 · ดีกรี@20 อัตโนมัติ) → กด **ปิด Batch**
→ เขียว "ปิด batch … แล้ว" ✅
- **ทดสอบกฎ 1 batch = 1 แถว:** ถ้าลองปิด batch เดิมซ้ำ ต้องขึ้นแดง "batch … ปิดไปแล้ว"

### 3.5 ปรุง / ปรับดีกรี (C1V1=C2V2)
แท็บ **ปรุง/ปรับดีกรี** → ชื่อสุรา **ยินทดสอบ** → เห็น "คงเหลือรอปรุง 10.00 ล."
- ติ๊ก "ระบบช่วยคำนวณ 2 ทาง" · ปริมาตรตั้งต้น **10** · ดีกรีตั้งต้น **78** · ดีกรีปลายทาง **40**
→ ปริมาตรปลายทาง + น้ำ ต้องคำนวณเอง (V2≈19.5, น้ำ≈9.5) → บันทึกปรุง ✅

### 3.6 บรรจุขวด (trigger สต็อก)
แท็บ **บรรจุ/จ่าย** → ประเภท **รับ** · สินค้า **ยินทดสอบ** · จำนวน **20** → บันทึก ✅
→ แท็บ **สต็อก**: `ยินทดสอบ = 20` ✅ (จากเดิม 0)

### 3.7 จ่ายออก
แท็บ **บรรจุ/จ่าย** → ประเภท **จ่าย** · สินค้า **ยินทดสอบ** · จำนวน **5** → บันทึก
→ แท็บ **สต็อก**: `ยินทดสอบ = 15` ✅

## ส่วนที่ 8 — ตรวจแท็บบัญชี (ต้อง login เป็น role `main`)

### 8.1 แดชบอร์ด
- แท็บ **แดชบอร์ด** → ควรเห็น: รายรับ 1,000 · รายจ่าย 3,000 (2,000+1,000) · ภาษีขาย 70 · ภาษีซื้อ 140
- กล่อง "รายจ่ายที่ยังไม่ออก 50ทวิ" = **2 รายการ** (นายทดสอบ 60 · บริษัททดสอบ 10)
- บิลค้าง AP (3,000) **ไม่นับ** ในรายจ่าย · เช็คราคา (T-TR-0007) **ไม่โผล่** ที่ไหนเลย

### 8.2 บัญชี & เงินสด
- แท็บ **บัญชี & เงินสด** → ยอด "กสิกร ทดสอบ": ยกมา 10,000 · คงเหลือ = 10,000 + (ขาย 1,070) − (ซื้อ 2,080 + ซื้อ 990 + โอนออก 500) = **7,500**
  - "เงินสด ทดสอบ" คงเหลือ 500 (รับโอน) · รวมทุกบัญชี 8,000
  - บิลค้าง AP (3,210) **ไม่กระทบยอด** (ยังไม่ชำระ)
- กด **statement** ของ "กสิกร ทดสอบ" → เห็นรายการเดือน 07 พร้อม running balance
- **โอนเงิน**: โอน 100 จากกสิกร→เงินสด → ยอดปรับทันที (กสิกร −100, เงินสด +100)

### 8.3 ลูกหนี้-เจ้าหนี้ (AP/AR)
- แท็บ **ลูกหนี้-เจ้าหนี้** → เจ้าหนี้ AP มี "ค่าซ่อมทดสอบ" 3,210
- กด **ชำระ** → เลือกบัญชี "กสิกร ทดสอบ" → **ยืนยันชำระ** → รายการหาย + ไปเข้ายอดบัญชี/รายงานตามวัน 2026-07
- ส่วนล่าง "ยอดค้างจากออเดอร์ขาย" = ว่าง (ยังไม่มี Phase 4)

### 8.4 บันทึกบิลใหม่ (entry + VAT/WHT)
- แท็บ **บันทึก** → ประเภท รายจ่าย · หมวด "ค่าบริการทดสอบ" · บัญชี "กสิกร ทดสอบ" · คู่ค้า "นายทดสอบ ใจดี"
- เพิ่มรายการ: ราคา/หน่วย 1000 จำนวน 1 → ติ๊ก VAT + หัก ณ ที่จ่าย 3% → สรุปควรได้ VAT 70 · WHT 30 · สุทธิ 1,040 → **บันทึก**

## ส่วนที่ 25 — ใบแจ้งหนี้ค่ามัดจำ (D45)

> เคสจริง: เสนอราคาแบบ "มัดจำ 50%" ลูกค้าขอ**ใบแจ้งหนี้ของยอดมัดจำ**ก่อนโอนเงิน
> โฟลว์ใหม่: `รอคอนเฟิร์ม` → **ใบแจ้งหนี้มัดจำ** → `รอชำระมัดจำ` → **รับมัดจำ & ส่งคลัง** → เหมือนเดิมทุกขั้น
> ⚠️ **ต้อง apply migration ก่อน ไม่งั้นหน้าขายเปิดไม่ขึ้น**

### 25.0 apply migration (ทำก่อนทุกข้อ)
```bash
npm run db:push
```
- **ควรเห็น**: `20260807000024_deposit_invoice.sql` ถูก apply

### 25.1 สร้างใบเสนอราคาแบบมีเงื่อนไขมัดจำ
- ขาย → แท็บ **สร้างใบเสนอราคา** → เลือกลูกค้าทดสอบ → ใส่สินค้า 2 รายการ
- ติ๊ก **กำหนดเงื่อนไขมัดจำ** → ใส่ **50**
  - **ควรเห็น**: สรุปยอดแสดง "เงินมัดจำที่คาดว่าจะได้รับ" = ครึ่งหนึ่งของยอดสุทธิ
- กด **บันทึกใบเสนอราคา** → ไปแท็บ **จัดการออเดอร์**

### 25.2 ออกใบแจ้งหนี้ค่ามัดจำ
- แถวออเดอร์ที่เพิ่งสร้าง (สถานะ `รอคอนเฟิร์ม`)
  - **ควรเห็น**: ปุ่ม **"ใบแจ้งหนี้มัดจำ"** เป็นปุ่มสีเข้ม (ปุ่มเด่นสุด เพราะใบเสนอราคานี้มีเงื่อนไขมัดจำ)
- กด **ใบแจ้งหนี้มัดจำ**
  - **ควรเห็น**: กล่อง "ออกใบแจ้งหนี้ค่ามัดจำ" · ยอด prefill = 50% ของยอดสุทธิ · ช่อง "ครบกำหนดชำระมัดจำภายใน (วัน)" = 7
  - **ควรเห็น**: กล่องคำอธิบายว่า "ยังไม่ลงบัญชีรับเงิน — เมื่อลูกค้าโอนแล้วให้กด รับมัดจำ & ส่งคลัง"
  - **ไม่ควรเห็น**: ช่อง "ช่องทางการชำระ" (ยังไม่ได้รับเงิน)
- กด **บันทึก**
  - **ควรเห็น**: สถานะเปลี่ยนเป็น **`รอชำระมัดจำ`** · มีปุ่ม "รับมัดจำ & ส่งคลัง" / "รับเต็ม & ส่งคลัง" / "ยกเลิกใบแจ้งหนี้มัดจำ"

### 25.3 พิมพ์ใบแจ้งหนี้มัดจำ (ตรวจหน้ากระดาษ)
- กด **พิมพ์ชุดแรก**
  - **ควรเห็น**: 2 หน้า (ต้นฉบับ + สำเนา) หัวกระดาษ **"ใบแจ้งหนี้ / Invoice"**
  - **ควรเห็น**: กล่องขวาบนมี 4 บรรทัด — เลขที่ (`INVyymmdd-NNN`) · วันที่ · **ครบกำหนด / Due** (วันที่ออก + 7) · อ้างอิง QU
  - **ควรเห็น**: ตารางสรุปเรียงลำดับ รวมเป็นเงิน → มูลค่าสินค้า (ก่อน VAT) → ภาษีมูลค่าเพิ่ม 7% →
    **ยอดรวมทั้งสิ้น** → แถวแดง **"ยอดชำระมัดจำ 50% สุทธิ"** → "คงเหลือเรียกเก็บเมื่อส่งมอบสินค้า"
  - **ควรเห็น**: กล่อง **ช่องทางการโอนเงิน** (สีเหลือง) + ช่องเซ็น "ผู้ชำระเงิน" กับ "ผู้มีอำนาจลงนาม"
  - **ไม่ควรเห็น**: คำว่า "ใบกำกับภาษี" ที่ไหนบนใบนี้

### 25.4 ⚠️ ต้องยังไม่ลงบัญชี (จุดสำคัญสุด)
- ไปแอป **บัญชี** → แท็บ **ค้นบิล** ค้นชื่อลูกค้าทดสอบ
  - **ควรเห็น**: **ไม่มี**รายการรับเงินของออเดอร์นี้ (ยังไม่ได้รับเงินจริง)
- แท็บ **AP/AR** → ตาราง "ยอดค้างออเดอร์ขาย"
  - **ควรเห็น**: ออเดอร์นี้ค้าง **เต็มยอด** (ยังไม่ได้หักมัดจำ เพราะยังไม่ได้รับเงิน)

### 25.5 รับเงินมัดจำจริง (ท่อเดิม)
- กลับหน้าขาย → ปุ่ม **รับมัดจำ & ส่งคลัง**
  - **ควรเห็น**: ยอด prefill = ยอดเดียวกับที่วางบิลไว้
- เลือกช่องทาง "โอนเงิน" → บันทึก
  - **ควรเห็น**: สถานะ `รอคลังจัดส่ง`
- กด **พิมพ์ชุดแรก**
  - **ควรเห็น**: 2 แบบเอกสาร — **ใบแจ้งหนี้/ใบส่งสินค้า** (มีแถว "หัก มัดจำรับแล้ว" + ยอดค้าง) และ
    **ใบกำกับภาษี/ใบเสร็จรับเงิน** ของค่ามัดจำ
  - **ควรเห็น**: เลขใบแจ้งหนี้ใบนี้ **คนละเลข** กับใบแจ้งหนี้มัดจำ (INV เรียงต่อกัน)
- ไปบัญชี → **ค้นบิล** → **ควรเห็น**: รายการรับเงินยอดมัดจำ ลงบัญชีแล้ว 1 รายการ (ไม่ซ้ำ)

### 25.6 ยกเลิกใบแจ้งหนี้มัดจำ (ลูกค้าเปลี่ยนออเดอร์)
- ทำ 25.1–25.2 ใหม่อีกใบ แล้วกด **ยกเลิกใบแจ้งหนี้มัดจำ** (เห็นเฉพาะ role `main`)
  - **ควรเห็น**: กล่องยืนยันบอกว่าออเดอร์จะกลับเป็น "รอคอนเฟิร์ม"
- ยืนยัน → **ควรเห็น**: สถานะกลับเป็น `รอคอนเฟิร์ม` · ปุ่ม **แก้ไข** กลับมา · แก้รายการสินค้าได้ตามปกติ
- ออกใบแจ้งหนี้มัดจำใหม่ → **ควรเห็น**: ได้เลข INV **ใบใหม่** (เลขเดิมถือว่ายกเลิก ไม่นำกลับมาใช้)
- login ด้วย role `sale` → **ควรเห็น**: **ไม่มี**ปุ่มยกเลิกใบแจ้งหนี้มัดจำ

### 25.7 เคสมี หัก ณ ที่จ่าย
- สร้างใบเสนอราคาที่ติ๊กทั้ง **หัก ณ ที่จ่าย 3%** และ **มัดจำ 50%** → ออกใบแจ้งหนี้มัดจำ → พิมพ์
  - **ควรเห็น**: ใต้ "ยอดรวมทั้งสิ้น" มี "หัก ณ ที่จ่าย 3%" แล้วต่อด้วย **"ยอดสุทธิ"**
    (แถวนี้ขึ้นเฉพาะเคสมี WHT) แล้วจึงเป็นยอดมัดจำ
  - **ควรไล่เลขได้ครบ**: ยอดรวมทั้งสิ้น − หัก ณ ที่จ่าย = ยอดสุทธิ · ยอดสุทธิ × 50% = ยอดมัดจำ
    · ยอดสุทธิ − ยอดมัดจำ = คงเหลือเรียกเก็บเมื่อส่งมอบ
  - ⚠️ **ยอดรวมทั้งสิ้นต้องยังไม่หัก WHT** (= มูลค่าสินค้า + VAT) — ต้องตรงกับใบกำกับภาษีที่จะออกตอนรับเงิน

- เลื่อนรอบแบบ anniversary ไม่ drift · trigger มิเรอร์ `billing_due_on` · ย้อนรายการล่าสุด
- ★ ลูกค้าที่**ถูกระงับยังอ่านข้อมูลตัวเองได้ที่ระดับ DB** (พิสูจน์ว่าไม่ได้ไปตัดที่ RLS)

### 31.2 ตั้งค่างวด (แท็บ "ค่างวด" ใน `/platform`)

| ตั้งวันเริ่ม **31 ม.ค.** รายเดือน → บันทึก | ครบกำหนด = **28 ก.พ.** |

### 31.3 ★★ บันทึกว่าจ่ายแล้ว — ข้อที่ห้ามพลาดที่สุด

ใช้ลูกค้าที่ตั้งวันเริ่ม **31 ม.ค.** ต่อจาก 31.2

| กด "บันทึก 1 รอบ" ครั้งที่ | ครบกำหนดต้องเป็น |
|---|---|
| 1 | **31 มี.ค.** ← ไม่ใช่ 28 มี.ค. |
| 2 | **30 เม.ย.** |
| 3 | **31 พ.ค.** ← กลับมาเป็น 31 ได้ = ไม่ drift |

> 🚨 ถ้าได้ 28 มี.ค. แปลว่ามีคนไปแก้ให้บวกจาก `current_period_end` แทนจุดยึด — **ผิด**
> ลูกค้าจะเสียวันไปเรื่อย ๆ โดยไม่มีอะไรฟ้อง (เหตุผลเต็มใน D59 ข้อ 1)

| ทดสอบต่อ | ควรเห็น |
|---|---|
| ดูประวัติการจ่าย | 3 แถว · แต่ละแถวบอกว่าจ่ายรอบนั้นแล้วดันไปถึงวันไหน |
| กด "ย้อนรายการล่าสุด" | ครบกำหนดถอยกลับเป็น **30 เม.ย.** และประวัติหายไป 1 แถว |
| ตั้งลูกค้าที่ค้างมา 3 รอบ แล้วกดจ่าย 1 ครั้ง | ยัง**เลยกำหนดอยู่** (ถูกต้อง — 1 การจ่าย = 1 รอบ) |
| การ์ดสรุปบนสุด | จำนวนเลยกำหนด/ใกล้ครบ และ **รายได้ต่อเดือน** (รายปีถูกหาร 12 ไม่ใช่บวกเต็ม) |

### 31.4 ★ แจ้งเตือนฝั่งลูกค้า (บันได 3 ขั้น)

ตั้งวันเริ่มของลูกค้าทดสอบให้ครบกำหนด **อีก 2 วัน** แล้วเปิดหน้าต่างส่วนตัวล็อกอินเป็น `owner-…`

| ทดสอบ | ควรเห็น |
|---|---|
| ล็อกอินเป็นเจ้าของกิจการ (role main) | **แถบเหลือง**บนหัวแอป บอกวันครบกำหนด + "ถ้าโอนแล้วข้ามข้อความนี้ได้เลย" |

| ติ๊ก "แจ้งเตือนค่าบริการในแอปของลูกค้า" ออก | **เงียบสนิท** ทั้งแถบและป๊อปอัพ |
| ตั้งสถานะเป็น "หยุดพักชั่วคราว" | เงียบเหมือนกัน (ตกลงกันแล้วว่าพัก ห้ามตื๊อ) |

### 31.5 ★ ระงับ / คืนสิทธิ์

| ทดสอบ | ควรเห็น |
|---|---|
| กด "ระงับการใช้งาน" → ยืนยัน | แถวขึ้นป้าย **ถูกระงับ** ทั้งแท็บค่างวดและแท็บลูกค้า |

### 34.2 ตั้งค่าการคำนวณ — ★ ข้อพิสูจน์ของงานทั้งก้อน

ระบบเปล่า ไม่มี preset ให้เลย (ตั้งใจ — ไม่มีเกณฑ์ของบริษัทใดในตัวสินค้า)
ให้ลองตั้งเกณฑ์ที่ **ซับซ้อนกว่าปกติ** ดูว่าระบบรับไหวจริงไหม:

1. **ค่าตั้งพื้นฐาน** → **ชั่วโมงทำงานต่อวัน** = 9 · **การปัดเศษ** = จำนวนเต็มบาท ·
   **บัญชีจ่ายเงินเดือน** = เลือกจากดร็อปดาวน์ (เป็นรายชื่อบัญชีจริงจากแอปบัญชี ไม่ใช่ช่องพิมพ์)
2. **ชุดอัตรา** → ใส่วันเริ่มมีผล + อัตรา/เพดานประกันสังคม + ขั้นบันไดภาษี → บันทึก
3. **กลุ่มพนักงาน** → สร้าง 2 กลุ่ม (เช่น `ช่าง` / `หัวหน้า`)
4. **ช่องที่ต้องกรอก** → `ot_work_h` (ชั่วโมง) · `sick_d` (วัน) · `personal_d` (วัน) · `score1` · `score2`
5. **ตัวแปรกลาง** (★ ใหม่ใน D67 — ต้องสร้างก่อน ไม่งั้นตั้ง OT ไม่ได้) → สร้าง 2 ตัว:

| รหัส | ตัวตั้ง | หารด้วย | ใช้กับใคร |
|---|---|---|---|
| `hourly_rate` | ฐานเงินเดือน | วันทำงานมาตรฐานของงวด → ชั่วโมงต่อวัน | พนักงาน**รายเดือน** |

> 🚨 **ข้อที่พลาดแล้วเจ็บเงียบ ๆ**: คนรายวันฐานเป็น "ค่าแรงต่อวัน" อยู่แล้ว **ห้ามหารจำนวนวันซ้ำอีก**

> · ★ ตรวจว่าแถวสูตรในตารางแสดงเป็น `ฐานเงินเดือน ÷ … ÷ …` ตรงกับที่ตั้งไว้

| ค่าตำแหน่ง | กรอกยอดเอง (manual) | ทุกกลุ่ม | ภาษี ✓ · ปกส. ✓ · **prorate ✓** · ฐานตัวแปร ✗ |

> ★ ธง **"ฐานตัวแปร"** = รายการนี้ถูกรวมเข้าฐานที่ตัวแปรกลางเอาไปคิดหรือไม่ ·

**ควรเห็น**: ตั้งได้ครบทุกข้อ **โดยไม่ต้องแก้โค้ดเลย** ← นี่คือสิ่งที่งานทั้งก้อนนี้ต้องพิสูจน์

### 34.5 ลงบัญชีตามขาที่ตั้งไว้ + ตัวเลขคุม + ถอน

> ขาไม่ได้ล็อกไว้ในโค้ดแล้ว (D67) — ที่เห็นบนหน้านี้คือขาที่ตั้งเองไว้ในข้อ 34.2/7

**🚨 ข้อสำคัญที่สุดของหัวข้อนี้: แถบตัวเลขคุมเหนือตารางขา**

| ทดสอบ | ควรเห็น |
|---|---|
| ดูแถบเหนือตารางขา ตอนตั้งครบ 3 ขาตามตาราง 34.2/7 | แถบ**เขียว** · *ยอดรวมของขาที่ตั้งไว้* = *ยอดที่ควรลงทั้งหมด (รวมเงินได้ + สมทบนายจ้าง)* |
| 🚨 ไปเพิ่มขาที่ยอด**ซ้อน**กับของเดิม (เช่นขาใหม่ยอด = *รวมเงินได้*) แล้วกลับมาดู | แถบเปลี่ยนเป็น**เหลือง** + บอกว่า **"เกิน … มีขาที่ยอดซ้อนกันอยู่ (จะลงรายจ่ายซ้ำ)"** · **แต่ยังกดลงบัญชีได้** (เตือนไม่บล็อกโดยตั้งใจ) |
| ปิดขาที่เพิ่งเพิ่มนั้น (ติ๊ก "เปิดใช้งาน" ออก) | กลับเป็นเขียว — **ขาที่ปิดอยู่ไม่ถูกนับ** |
| ลองปิดขา *นำส่งประกันสังคม* | เหลือง + บอกว่า **"ขาด …"** (ยังมีส่วนที่ไม่ได้ลงบัญชี) |

**แล้วค่อยลงบัญชีจริง** (เปิดขาให้ครบ 3 ขาก่อน)

| ทดสอบ | ควรเห็น |
|---|---|
| ดูช่องวันที่ก่อนกด | เว้นว่างไว้ได้ — แต่ละขาจะใช้**วันที่แนะนำของตัวเอง** (สิ้นงวด+15 / +7 / วันจ่าย) |
| กด **ลงบัญชี** ที่ขา *จ่ายเงินเดือน* | ขึ้น "ลงแล้ว" · ไปแท็บ บัญชี → **ค้นบิล** เห็นรายจ่าย **1 รายการต่อพนักงาน 1 คน** (เพราะติ๊ก "แยกรายคน") |
| ดูหมวดรายจ่ายของรายการนั้นในบัญชี | ตรงกับที่**พิมพ์เอง**ในขา (`เงินเดือน`) — ไม่ต้องมีในรายการหมวดเดิมของแอปบัญชี |
| กดลงบัญชีขาเดิมซ้ำ | ถูกปฏิเสธว่าลงไปแล้ว · **ไม่เกิดรายการเพิ่มในบัญชี** |
| กลับมาแก้ตัวเลขในตารางงวด | **แก้ไม่ได้** (ช่องเป็นอ่านอย่างเดียว) + มีแถบเตือนว่าต้องถอนก่อน |
| ลงขา *นำส่งประกันสังคม* และ *นำส่งภาษี* | ได้อย่างละ **1 รายการรวม** (ไม่ติ๊กแยกรายคน) · ยอด ปกส. = ลูกจ้าง + นายจ้าง · คู่ค้าบนรายการเป็นชื่อที่พิมพ์ไว้ ไม่ใช่ชื่อพนักงาน |
| ★ บวกยอดทั้ง 3 รายการในบัญชี | ตรงกับ *ยอดที่ควรลงทั้งหมด* บนแถบตัวเลขคุมพอดี |
| 🚨 กด **ถอน** ขาจ่ายเงินเดือน แล้วไปดูในบัญชี | รายการกลายเป็นสถานะ **"ยกเลิก" ไม่ใช่หายไป** (ตรวจย้อนหลังได้ว่าเคยลงแล้วถอนเมื่อไหร่) |
| ถอนครบทุกขาแล้วแก้ตัวเลขใหม่ → ลงบัญชีอีกครั้ง | ทำได้ ไม่ติดว่า "ลงไปแล้ว" |

### 34.5b แท็บ "รายงาน" (★ ใหม่ใน D67)

> ทำไมต้องมี: บัญชีลงเป็น**ก้อน** จึงไม่รู้ว่าในก้อนนั้นเป็นเงินเดือนเท่าไร OT เท่าไร → มาดูที่นี่

### 34.6 🪤 แก้เกณฑ์แล้วงวดเก่าต้องไม่ขยับ

> ข้อนี้สำคัญที่สุดในส่วนนี้ — ถ้าพลาด ตัวเลขที่ยื่นราชการไปแล้วจะเปลี่ยนย้อนหลังเงียบ ๆ

1. จดยอดสุทธิของพนักงาน 1 คนในงวดที่**ลงบัญชีไปแล้ว**
2. ไปแท็บ **ตั้งค่าการคำนวณ** → แก้เบี้ยขยันขั้นบันได (เช่นเปลี่ยน `1=500` เป็น `1=900`)
3. กลับมาเปิดงวดเดิม

**ควรเห็น**: ตัวเลขในงวดนั้น **เท่าเดิมทุกบาท** (ค่าถูกแช่ไว้ตอนกดบันทึก)
· งวด**ใหม่**ที่สร้างหลังจากนี้ถึงจะใช้เกณฑ์ใหม่

### 34.10 ตัวแปรกลาง: ตัวดำเนินการ + ความละเอียด · ย้ายลำดับคอลัมน์ (D70 · migration 0044)

> ⚠️ ต้องลง **0044** ก่อน (`npm run db:push:all -- --apply`)

#### 34.10.1 🔴 ของเดิมต้องไม่ขยับ (ทำก่อนอย่างอื่น)

| ทดสอบ | ควรเห็น |
|---|---|
| เปิดแท็บตั้งค่า → **ตัวแปรกลาง** ดูตัวแปรที่ตั้งไว้ก่อนอัปเดต | คอลัมน์สูตรอ่านได้เหมือนเดิม (เช่น `ฐานเงินเดือน ÷ วันมาตรฐาน ÷ ชม./วัน` แสดงเป็นวงเล็บครบ) |
| ช่อง **ความละเอียดของค่าที่ได้** ของตัวแปรเดิม | เป็น **ไม่ปัด (ค่าเต็มความละเอียด)** — ถ้าขึ้นเป็นจำนวนเต็ม แจ้งทันที |
| 🔴 เปิดงวดเก่าที่บันทึกไว้แล้ว | ตัวเลข **เท่าเดิมทุกบาท** (ค่าแช่ไว้ + ค่าปริยายเดิมไม่ขยับ) |

#### 34.10.2 ตัวดำเนินการ 4 ตัว

1. แก้ตัวแปร → กด **+ เพิ่มขั้น** → เลือกตัวดำเนินการจากดร็อปดาวน์ (บวก/ลบ/คูณ/หาร)

| ทดสอบ | ควรเห็น |
|---|---|
| ตั้ง: ตัวตั้ง = ฐานเงินเดือน · ขั้น 1 = **บวก** ค่าคงที่ 2000 · ขั้น 2 = **หาร** 30 | กล่อง **"สูตรที่จะถูกใช้จริง"** ขึ้น `((ฐานเงินเดือน + 2000) ÷ 30)` |
| 🚨 สลับเป็น: ขั้น 1 = **ลบ** 3000 · ขั้น 2 = **หาร** 3 | ขึ้นแถบเตือนสีเหลืองว่าระบบคิด**เรียงซ้ายไปขวา** ไม่ได้คิดคูณ/หารก่อน |
| ★ ตรวจว่าเข้าใจตรงกัน: ฐาน 18,000 · ลบ 3,000 · หาร 3 | ต้องได้ **5,000** ไม่ใช่ 17,000 (ถ้าได้ 17,000 = ระบบไปคิดแบบกฎคณิตศาสตร์ แจ้งทันที) |
| เพิ่มขั้นที่ 4 | **ไม่มีปุ่มให้กด** — จำกัด 3 ขั้นโดยตั้งใจ |
| ตั้งขั้นเป็น **หาร** ด้วยค่าคงที่ 0 | ขึ้นเตือนว่า "ขั้นนี้จะถูกข้ามทุกครั้ง" |

#### 34.10.3 🪤 หารด้วย 0 ข้าม · คูณด้วย 0 ไม่ข้าม

| ทดสอบ | ควรเห็น |
|---|---|
| ตั้งตัวแปร: ฐานเงินเดือน **หาร** ช่องกรอก `ot_work_h` → เปิดงวดที่ยังไม่กรอก OT | ค่าตัวแปร = **ฐานเงินเดือน** (ขั้นนั้นถูกข้าม) ไม่ใช่ error / ยอดว่าง |
| เปลี่ยนเป็น **คูณ** ช่องเดียวกัน → งวดที่ยังไม่กรอก OT | ค่าตัวแปร = **0** (ไม่ข้าม) · ถ้าได้ฐานเงินเดือนกลับมา = ผิด แจ้งทันที |

#### 34.10.4 ความละเอียดของค่า

| ทดสอบ | ควรเห็น |
|---|---|
| ตั้งอัตราที่หารแล้วไม่ลงตัว (เช่น 18,000 ÷ 30 ÷ 9 = 66.67) → เลือก **จำนวนเต็ม** | สูตรต่อท้ายว่า "→ ปัดเป็นจำนวนเต็ม" · ยอด OT ที่คิดจากอัตรานี้ใช้ **67** |
| เปลี่ยนเป็น **ทศนิยม 2 ตำแหน่ง** | ใช้ **66.67** |
| เปลี่ยนกลับเป็น **ไม่ปัด** | ใช้ 66.6666… (ยอดต่างจาก 2 แบบบนเล็กน้อย — ถูกต้อง) |
| 🚨 หลังแก้ความละเอียด กลับไปดู**งวดที่บันทึกไปแล้ว** | ตัวเลข**เท่าเดิม** (ค่าแช่ไว้ตอนกดบันทึก) · งวดใหม่ถึงจะใช้ค่าใหม่ |

#### 34.10.5 ย้ายลำดับคอลัมน์ที่กรอก

| ทดสอบ | ควรเห็น |
|---|---|
| ตั้งค่า → **ช่องที่ต้องกรอกต่อคนต่องวด** → กด ▲ ที่ช่องล่างสุด | แถวขยับขึ้น**ทันที** ไม่ต้องรีเฟรช |
| ไปแท็บ **งวดจ่าย** | ลำดับคอลัมน์ในตารางเปลี่ยนตาม |
| กด F5 แล้วดูใหม่ทั้ง 2 แท็บ | ลำดับยังเป็นอันใหม่ (บันทึกลง DB จริง ไม่ใช่แค่บนจอ) |

| เพิ่มช่องใหม่ | ไปต่อท้ายสุดตามเดิม แล้วย้ายขึ้นได้ |
| 🪤 ย้ายลำดับแล้วเปิดงวดที่กรอกข้อมูลไว้แล้ว | **ค่าที่กรอกไว้ยังอยู่ครบ** (ย้ายคอลัมน์ ไม่ใช่ลบแล้วสร้างใหม่) |

### 34.11 หน้าตั้งค่า: บั๊กที่แก้ + กล่องรวม (D71 · ไม่มี migration)

#### 34.11.1 🔴 บั๊กที่แก้ — ต้องยืนยันว่าหายจริง

| ทดสอบ | ควรเห็น |

| ลบเงื่อนไขตรงกลาง | ลบเฉพาะแถวนั้น แถวอื่นอยู่ครบ |
| 🔴 กด **บันทึก** โดยไม่กรอกรหัส | ข้อความเตือนขึ้น**ในป๊อปอัพ** (เดิมไปขึ้นหลังป๊อปอัพจนมองไม่เห็น) |

#### 34.11.2 กล่องรวม + สูตรที่จะถูกใช้จริง

| ทดสอบ | ควรเห็น |
|---|---|
| เปิดแท็บตั้งค่า | มีการ์ด **สูตรและรายการคำนวณ** การ์ดเดียว · ในนั้นแยกหัวข้อ **ตัวแปร — คิดก่อน** และ **รายการเพิ่ม/หัก — คิดทีหลัง** |
| กด **+ รายการเพิ่ม/หัก** แล้วสลับตัวเลือกบนสุดเป็น **ตัวแปร** | ฟอร์มเปลี่ยนเป็นของตัวแปรครบ (ตัวตั้ง/ขั้น/ความละเอียด) ไม่มีธง 4 ตัวค้าง |
| กด **แก้** ของที่บันทึกแล้ว | **ไม่มี**ตัวเลือกสลับชนิด (ย้ายข้ามชนิดไม่ได้โดยตั้งใจ) |
| ดูคอลัมน์ **สูตรที่ใช้จริง** ในตารางรายการ | อ่านรู้เรื่องทุกแถว เช่น `อัตราต่อชั่วโมง × 1.5 × (OT วันทำงาน)` |
| ตั้งรายการที่ใช้ **หลายช่องกรอก** แล้วเลือก *เฉลี่ย* | สูตรเขียนว่า `(ลาป่วย เฉลี่ยกับ ลากิจ)` — เดิมมองไม่เห็นเลยว่าตั้งแบบไหนไว้ |
| 🪤 เลือกวิธีคิด **ตัวแปรกลาง** แล้วตั้งตัวคูณเป็น **0** | ขึ้นเตือนว่า *ยอดจะเป็น 0 ทุกงวด* (เตือนไม่บล็อก) · รายการใหม่เริ่มต้นตัวคูณ = **1** |
| ใช้ตัวแปรตรง ๆ: ตัวคูณ 1 + ไม่ติ๊กช่องกรอกเลย | สูตรเขียนว่า `… × 1 (ไม่คูณหน่วย)` |

#### 34.11.3 ของเดิมต้องไม่ขยับ

| ทดสอบ | ควรเห็น |
|---|---|
| เปิดงวดที่บันทึกไว้แล้ว | ตัวเลขเท่าเดิมทุกบาท (รอบนี้ไม่แตะสูตรและไม่มี migration) |
| ตัวแปร/รายการที่ตั้งไว้ก่อนอัปเดต | ค่าครบเหมือนเดิม แค่ย้ายมาอยู่ในการ์ดเดียว |

### 34.12 หน้าตั้งค่า: ไม่ต้องตั้งรหัสเอง · ยืนยันก่อนลบ · หมวด/คู่ค้ามีตัวช่วย (D72)

| ทดสอบ | ควรเห็น |
|---|---|
| เปิดแท็บ **ตั้งค่าการคำนวณ** ไล่ดูทุกการ์ด | **ไม่มีช่อง "รหัส (a-z 0-9 _)" เหลืออยู่เลย** และตารางช่องกรอกไม่มีคอลัมน์รหัส |
| เพิ่มช่องกรอก / ตัวแปร / รายการ / ขา อย่างละ 1 อัน | บันทึกผ่านโดยไม่ต้องกรอกรหัส |
| 🚨 **แก้ของเดิมแล้วบันทึก** → ไปดูงวดที่บันทึกไว้ก่อนหน้า | ตัวเลข**เท่าเดิมทุกบาท** (รหัสของเดิมต้องไม่ถูกเปลี่ยน — ถ้ายอดกลายเป็น 0 แปลว่ารหัสขยับ แจ้งทันที) |
| กดปุ่ม **ลบ** / **✕** ทุกจุดในหน้า (กลุ่ม · ช่องกรอก · ตัวแปร · รายการ · ขา) | ขึ้นกล่องยืนยันพร้อม**ชื่อของจริง** ทุกจุด · กด *ยกเลิก* แล้วของยังอยู่ครบ |
| แก้ **ขาลงบัญชี** → ช่อง **หมวดรายจ่าย** | พิมพ์เองได้ **และ**กดแล้วมีรายการหมวดที่เคยใช้ให้เลือก |
| ช่อง **คู่ค้าบนรายการ** | เหมือนกัน — มีชื่อคู่ค้าที่มีอยู่ให้เลือก แต่พิมพ์ชื่อใหม่ได้ |
| ตั้งหมวดใหม่ที่ยังไม่เคยมี → บันทึก → เปิดขาอื่น | หมวดที่เพิ่งตั้ง**ขึ้นเป็นตัวเลือก**ให้ด้วย (ไม่ต้องพิมพ์ซ้ำ) |

### 34.13 งวดจ่ายโชว์ค่าที่บันทึกไว้ · ป๊อปอัพ (D73 · ไม่มี migration)

#### 34.13.1 🔴 เปลี่ยนเกณฑ์แล้วงวดที่บันทึกไว้ต้องไม่ขยับบนหน้าจอ

| ทดสอบ | ควรเห็น |
|---|---|
| จดยอดสุทธิของงวดที่**บันทึกแล้ว** ไว้ 1 คน → ไปลบรายการเพิ่ม/หัก 1 ตัวทิ้ง | |
| กลับมาเปิดงวดเดิม | ตัวเลข **เท่าเดิม** (ค่าที่บันทึกไว้) + มี**แถบเหลือง**บอกว่าเกณฑ์เปลี่ยนไปและมีกี่คนที่ยอดใหม่ไม่ตรง |
| เทียบกับแท็บ **รายงาน** | ตรงกัน (เดิมหน้างวดจ่ายโชว์ยอดใหม่ รายงานโชว์ยอดเก่า = ขัดกันเอง) |
| แก้ตัวเลขในช่องกรอกของคนใดคนหนึ่ง | **เฉพาะแถวนั้น**เปลี่ยนเป็นยอดที่คิดสด (แถวอื่นยังเป็นค่าที่บันทึกไว้) |
| กด **คำนวณ & บันทึก** | ทุกแถวอัปเดตเป็นเกณฑ์ใหม่ · แถบเหลืองหาย · รายงานเปลี่ยนตาม |

#### 34.13.2 ป๊อปอัพ (ทดสอบได้ทุกป๊อปอัพในแอป ไม่เฉพาะเงินเดือน)

| ทดสอบ | ควรเห็น |
|---|---|
| 🔴 เปิดป๊อปอัพ → **ลากคลุมข้อความ**ในช่องกรอกแล้วปล่อยเมาส์นอกช่อง | ป๊อปอัพ**ยังเปิดอยู่** (เดิมปิดเองแล้วงานที่พิมพ์หาย) |
| กดพื้นหลังสีเทาตรง ๆ | ปิดตามปกติ |
| กด **Esc** | ปิด |
| ลองที่ บัญชี → บันทึก/ค้นบิล · ตั้งค่า → สำรองข้อมูล · เงินเดือน → พนักงาน/เอกสารยื่น | พฤติกรรมเหมือนกันทุกที่ |
| ป๊อปอัพแจ้งเตือน**ค่างวด** (ถ้าเจอ) | กด Esc **ไม่ปิด** — ตั้งใจให้ต้องอ่าน |
