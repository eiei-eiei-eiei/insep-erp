## 1. ⚠️ ตัวบล็อกการขาย — เอกสารการค้ายังเป็นชื่อบริษัทผู้ใช้ (สำคัญสุด)

**เจอตอนท้าย session D43 ยังไม่ได้แก้**

`app/(app)/sales/_components/print.ts:15-20` มีค่าคงที่ hardcode:

```ts
const COMPANY = {
  name: "บริษัท อินทร์ เสพเทมเบ้อ จำกัด",
  nameEng / address / taxLine,
  bank: "ธนาคารกสิกรไทย เลขที่บัญชี 195-1-19799-4 …",
};
```

**ผลถ้าขายทั้งอย่างนี้**: ลูกค้าออกใบเสนอราคา/ใบกำกับภาษี/ใบเสร็จ → หัวกระดาษเป็นชื่อบริษัทผู้ใช้
พร้อม **เลขบัญชีธนาคารของผู้ใช้** → เงินเข้าผิดบัญชี + ใบกำกับภาษีผิดนิติบุคคล (ผิดกฎหมาย)

**ข่าวดี**: กระทบเฉพาะเอกสารการค้า · **ฟอร์มราชการปลอดภัยแล้ว**
(ภพ.30 / ภงด. / 50ทวิ / ภส. ดึงจากตาราง `entities` ซึ่งเป็นข้อมูลต่อกิจการอยู่แล้ว)

**วิธีแก้ที่วางไว้**:
1. ย้ายค่าใน `COMPANY` ไปอ่านจาก `entities` (มี name/tax_id/branch/address อยู่แล้ว)
   — ต้องเพิ่มคอลัมน์ที่ยังไม่มี: `name_eng`, `bank_line` (หรือเก็บใน `app_settings`)
2. `printQuotation` / `printSalesDocs` รับ company info เป็น argument แทน constant
3. ⚠️ **ต้องเทียบเอกสารก่อน-หลังให้เหมือนเป๊ะ** — ผู้ใช้พิมพ์เอกสารนี้ทุกวัน
   ห้ามให้ layout ขยับ · ทำตอนมีเวลาเทสยาว ๆ ไม่ใช่แทรกงานอื่น

## 2. 🔵 ตัดสินใจค้าง: white-label เต็ม vs co-brand

**ผู้ใช้ยังไม่ตอบ — ต้องถามก่อนทำข้อ 3**

หน้า `/login` อ่านชื่อแบรนด์จาก DB ไม่ได้ (ยังไม่ login = RLS บล็อก `app_settings`)
ตอนนี้ hardcode `"Insep ERP"` + `"ระบบภายในโรงกลั่นสุราคราฟต์"` ใน `app/(auth)/login/page.tsx`

| โมเดล | ลูกค้าเห็น | ผล |
|---|---|---|
| **A. White-label เต็ม** | แบรนด์ตัวเองล้วน ตั้งแต่หน้า login | ขายได้ราคาสูงกว่า · ผู้ใช้ไม่ได้ exposure |
| **B. Co-brand** (Claude แนะนำ) | โลโก้ลูกค้าเด่น + `powered by [ชื่อสินค้า]` เล็ก ๆ | ได้บอกต่อฟรีทุกวัน · ตลาดโรงคราฟต์ไทยรู้จักกันหมด |

ถ้าเลือก A: ชื่อ/โลโก้หน้า login ต้องมาจาก **env var ต่อ deployment** (`NEXT_PUBLIC_BRAND_NAME`)
เพราะอ่าน DB ไม่ได้ก่อน login

**ชื่อสินค้ายังเป็น TBC** — ผู้ใช้ยังไม่เคาะ (เคยใช้ชื่อสมมติว่า "กลั่น")

## 4. งาน productization ก้อนใหญ่ (ยังไม่เริ่ม — วางแผนไว้แล้ว)

> รายละเอียดการตัดสินใจอยู่ใน memory `productization-plan` และ `docs/DECISIONS.md`
> ผู้ใช้ตั้งใจ **ทำทีเดียวเป็นก้อน** ไม่ทำแทรกทีละนิด

1. **Module feature flags** — `modules_enabled` ต่อ tenant (ผลิต/บัญชี/ขาย ขายแยกได้ 7 SKU)
   gate ที่ nav + route/server-action + จุดเชื่อมข้ามโมดูล (`if (enabled)`)
2. **Generalize multi-entity** — ตอนนี้จูนมาสำหรับกิจการหลาย entity ของผู้ใช้เอง
   ลูกค้าทั่วไปมีกิจการเดียว → ทำให้ EID เป็น optional/config
3. **ประเภทโรงงาน กลั่น vs แช่** — เพิ่ม flag ต่อ tenant
   - กลั่น (ปัจจุบัน): หมัก→กลั่น→ปรุง→บรรจุ + ฟอร์ม ภส. ชุดกลั่น
   - แช่ (เบียร์/ไวน์/สาโท): หมัก→บ่ม→บรรจุ **ไม่มีขั้นกลั่น** + ฟอร์ม ภส. คนละชุด
   - ⚠️ **ติดที่ยังไม่มีเทมเพลตฟอร์มสุราแช่จากสรรพสามิต** — ผู้ใช้มีแต่ฟอร์มกลั่น
   - ⚠️ **ห้ามใส่โหมดแช่ลงระบบที่ผู้ใช้ใช้จริง** (เขาไม่ได้ทำแช่) — ทำเป็น config เท่านั้น
4. **Provision script** — สร้างลูกค้าใหม่: สร้าง Supabase project → migrate → seed → deploy Vercel → ตั้ง env
   + secrets registry + fleet cron (keep-alive + backup)
   ⚠️ **นี่คือของที่จะกินเวลาจริงตอนมีลูกค้า 10 ราย** ไม่ใช่เรื่องสี — migration ต้องรันทุก tenant
5. **ตัด/ลดความสำคัญฟีเจอร์สแกนใบเสร็จ AI** — memory `receipt-scan-thai-unreliable` บอกว่าอ่านไทยไม่แม่นพอ

## 7. บทเรียนจาก D43 (อ่านก่อนแก้ UI/เขียนสคริปต์)

1. **selector trap**: `data-mode` อยู่บน `<html>` แต่ `data-brand` อยู่บน div ใน `(app)/layout.tsx`
   → `[data-mode="dark"][data-brand="x"]` **ไม่ match** ต้องเขียนคู่กับแบบลูกหลาน
   **build ผ่านทั้งที่สีผิด** — จับได้ตอนอ่าน computed style ในเบราว์เซอร์เท่านั้น
2. **สคริปต์ sweep**: ห้าม `replace()` แบบ global ที่แตะ `"` — รอบแรกไปกิน string literal ทั้งไฟล์
   (`from "react"` → `from"react"`) ต้อง revert · แก้เฉพาะ "ภายในค่าของ className"
3. **หลัง sweep สีอัตโนมัติ ต้องไล่หาคู่ `bg-x` + `text-x` ที่เป็น token เดียวกัน**
   (เจอปุ่มสแกนใบเสร็จกลายเป็น `bg-brand text-brand` = ตัวหนังสือหายไปกับพื้น)
4. **ไฟล์เอกสารพิมพ์ห้ามผูกกับธีม**: `print.ts` · `reportHtml.ts` · `lib/pdf/*`
   ต้องดำบนขาวเสมอ ไม่งั้นเปิดโหมดมืดแล้วพิมพ์ = กระดาษพื้นดำ
5. **ตรวจสีดิบเหลือ 0**:
   ```bash
   grep -rn "\(bg\|text\|border\)-\(slate\|amber\|green\|red\|blue\)-[0-9]" app --include=*.tsx | grep -v print.ts
   ```
