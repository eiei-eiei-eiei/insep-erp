## ตัดสินใจแล้ว (2026-08-24)

1. **เส้นทางข้อมูล "แยกน้ำสุราแช่ออกจากถังหมัก" = ตารางใหม่แยก ไม่ reuse `log_distill`**
   เหตุผลของผู้ใช้: ยอมรับว่ามีโค้ด 2 ที่ทำเรื่องคล้ายกัน เพื่อแลกกับการที่อนาคตแก้ดีเทล
   เฉพาะของ *การกลั่น* หรือ *การแช่* ได้โดยไม่กระทบกันเอง (reuse แล้วแก้ยากมาก)
   → กติกาเหล็ก *1 batch = 1 แถว* ต้องยกมาใช้กับตารางใหม่ด้วย **ถ้า** ตอบข้อค้าง (ก) ด้านล่าง

2. **ธง กลั่น/แช่ = อ่านจาก `products.liquor_type` (ประเภทสุรา) ตัวเดิม ไม่เพิ่มคอลัมน์**
   บนจอเปลี่ยนเป็นดร็อปดาวน์ให้เลือกได้แค่ `สุรากลั่น` / `สุราแช่`
   หลักฐานว่าปลอดภัย: `liquor_type` = ช่อง "ประเภทสุรา" ที่**พิมพ์ลงหัวฟอร์ม ภส. อยู่แล้ว**
   (`excise.ts` 4 ฟอร์ม) และตามกฎหมายสรรพสามิต ประเภทสุรามีแค่ 2 ค่านี้จริง —
   ส่วนชื่อเชิงพาณิชย์อยู่ที่ `liquor_kind` (ชนิดสุรา) แยกกันอยู่แล้ว
   ข้อมูลจริงใน `migration/csv/production.xlsx` → Master_Product 10 แถว:
   ประเภทสุรา = "สุรากลั่น" 10/10 · ชนิดสุรา = "สุราขาว" 10/10 → ใส่ดร็อปดาวน์ 2 ค่าไม่ทำข้อมูลเดิมพัง
   - 🚨 **ห้ามใส่ CHECK constraint ใน migration ทันที** — `db:push:all` ลงทุก DB รวมของลูกค้า
     ที่เราไม่เคยเห็นข้อมูล ถ้าใครพิมพ์ค่าอื่นไว้ = migration ล้มทั้ง fleet · บังคับที่ดร็อปดาวน์
     + server action ก่อน แล้วค่อยพิจารณา CHECK เป็น migration แยกหลังตรวจข้อมูลทุกก้อน
   - 🚨 **`products` มีหลายแถวชื่อสุราเดียวกันได้** (ขนาดขวดต่างกัน) และรายงาน ๐๗-๐๒/๑ aggregate
     ตาม *ชื่อ* (`reports.ts` เลือก `anyP` = แถวแรกที่ชื่อตรง) → ถ้าแถวชื่อเดียวกันมีประเภทสุราไม่ตรงกัน
     ระบบจะหยิบมาแถวเดียวเงียบ ๆ = เลือกฟอร์มผิดใบ **ต้องเตือน ไม่ใช่เดา**
   - 🚨 ประเภทสุราว่าง/ไม่ใช่ 2 ค่านี้ → **ไม่ออกฟอร์ม เตือนให้ไปตั้งค่าก่อน** ห้าม default เป็นกลั่น
   - 📌 เฟสเบียร์: เบียร์เป็น **ชนิด** ของ **ประเภทสุราแช่** (ไม่ใช่ประเภทที่ 3) และใช้ฟอร์มคนละใบอีกใบ
     → ตอนนั้นการเลือกฟอร์มต้องดูคู่ (ประเภท, ชนิด) **ออกแบบสวิตช์ให้โตไปทางนั้นได้ตั้งแต่ตอนนี้**

3. **แรงแอลกอฮอล์ (ดีกรี)** — ผู้ใช้กรอกตอนบันทึกการแยกน้ำสุรา (คอลัมน์ในตารางใหม่ ข้อ 1)

4. **แถวรวม** ยึดตามฟอร์มกลั่นเดิม:
   - รวมเดือนนี้ = ปริมาณสุทธิน้ำหมัก · ปริมาณน้ำสุราแช่ · น้ำหมักคงเหลือ · ปริมาณสุทธิบรรจุ · สุราแช่คงเหลือ
   - รวมแต่ต้นปี = ปริมาณสุทธิน้ำหมัก · ปริมาณน้ำสุราแช่ · ปริมาณสุทธิบรรจุ (ไม่รวมยอดคงเหลือ)

## ปิดข้อค้างแล้ว (2026-08-24)

**"ปริมาณน้ำหมักคงเหลือ" ตัดยังไง** → ผู้ใช้เลือก **(ก) หักน้ำหมักทั้ง batch ออกเมื่อรินครั้งเดียวจบ**
→ ตารางใหม่ `log_ferment_draw` มี `unique (tenant_id, entity_id, batch)` = ยกกติกาเหล็ก
*1 batch = 1 แถว* มาใช้เต็มรูปแบบ (รินซ้ำ = หักน้ำหมักซ้ำ = เลขยื่นราชการผิด)

**ขั้นปรุงก่อนบรรจุ** → ผู้ใช้ยืนยันว่า **มี** (เติมน้ำ/น้ำตาล) แต่ฟอร์มไม่มีคอลัมน์รองรับ
→ เก็บไว้แถวเดียวกับการริน (`final_vol`/`final_abv`/`water`/`adjust_date`) และ**ลงฟอร์มด้วยยอดหลังปรุง**

## 🔴 ยังต้องยืนยันกับเจ้าหน้าที่สรรพสามิต

**คอลัมน์ "ปริมาณน้ำสุราแช่" = ยอดก่อนปรุง (160) หรือหลังปรุง (200)?**
ระบบเลือก **หลังปรุง** เพราะหัวคอลัมน์เขียนว่า "ที่ผลิตได้**และรอบรรจุ**" และเป็นทางเดียวที่
ยอดคงเหลือจะตรงกับยอดบรรจุ (ลง 160 แต่บรรจุ 200 = ช่องคงเหลือติดลบ)
→ ถ้าคำตอบเป็น "ก่อนปรุง" แก้ที่ `drawnVol()` / `drawnAbv()` ใน `lib/production/calc.ts` **จุดเดียว**
