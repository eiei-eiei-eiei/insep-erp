# ปิดเดือนบัญชี (Insep ERP)

ใช้เครื่องมือของ connector Insep ERP เท่านั้นในการอ่าน/บันทึกข้อมูล — skill นี้คือ "ลำดับงาน" ส่วนตัวเลขทั้งหมดมาจากระบบ

## กติกาที่ห้ามข้าม

- **ตัวเลขภาษีมาจาก `tax_report` เท่านั้น** ห้ามคำนวณ VAT/ภาษีหัก ณ ที่จ่ายเอง ห้ามปรับตัวเลข ถ้าดูแปลกให้บอกผู้ใช้ว่าแปลกตรงไหน
- **ห้ามแก้ยอดเงินของบิลที่มีอยู่แล้ว** — ถ้าเจอบิลยอดผิด/ลงผิดบัญชี/ผิดเดือน ให้รายงานพร้อมเลข `tx_id` แล้วบอกให้ผู้ใช้ไปแก้ในแอป (บัญชี → ค้นบิล) · `edit_bill` ใช้ได้เฉพาะเปลี่ยนหมวด/งาน/บัญชี/คู่ค้า ของบิลที่ Claude ลงเอง
- **บิลที่ขาด ลงผ่านการ์ดเท่านั้น** (`preview_bill` → ผู้ใช้กดบันทึกบนการ์ด) และต้องมีรูปบิลจริงจากผู้ใช้ — ห้ามสร้างบิลจากบรรทัด statement อย่างเดียว
- ปี: statement ไทยมักเป็น พ.ศ. → เครื่องมือรับ **ค.ศ.** เสมอ (ลบ 543)
- ไม่ต้องกดยื่นหรือบันทึกจ่ายแทนผู้ใช้ — Claude ทำไม่ได้ และไม่ควรทำ

## ขั้นตอน

### 1. ตั้งต้น
- เรียก `who_am_i` ดูว่ามีกิจการอะไรบ้าง และกิจการไหนจด VAT
- ถามผู้ใช้ (ถ้ายังไม่บอก): เดือนไหน · กิจการไหน · statement นี้คือบัญชีไหนในระบบ (ชื่อบัญชีดูจาก `lookup_options`)

### 2. กระทบยอดทีละบัญชี
- อ่าน statement ที่ผู้ใช้ส่งมา (ไฟล์/รูป) แล้วเรียก `account_statement` ของบัญชีเดียวกัน เดือนเดียวกัน
- จับคู่บรรทัดด้วย ยอดเงิน + วันที่ใกล้กัน (ธนาคารอาจลงช้ากว่า 1-3 วัน) · ทิศ: `in` = เงินเข้า `out` = เงินออก
- ยอดใน statement ธนาคารคือ **เงินที่โอนจริง = ยอดสุทธิหลังหัก ณ ที่จ่าย** (`net`)
- บรรทัดที่หาไม่เจอในบัญชีนั้น → ลอง `search_transactions` ด้วยยอดเงินและช่วงวันที่ ±7 วัน (ไม่ใส่ `account_name`) เพื่อดูว่าลงผิดบัญชี/ผิดเดือนไหม
- เทียบยอดคงเหลือปลายเดือนของ statement กับ `closing_balance`

### 3. รายงานผล 3 กลุ่ม (ตารางสั้น ๆ)
1. **มีในธนาคาร ไม่มีในระบบ** — บิลที่ยังไม่ได้ลง → ขอรูปบิลจากผู้ใช้ แล้วลงด้วย `preview_bill` ทีละใบ (ถ้าเป็นค่าธรรมเนียมธนาคาร/ดอกเบี้ยที่ไม่มีบิล ให้ถามผู้ใช้ว่าจะลงหมวดอะไร)
2. **มีในระบบ ไม่มีในธนาคาร** — อาจลงผิดบัญชี/ผิดเดือน/ลงซ้ำ/ยังไม่ได้จ่ายจริง → บอก `tx_id` และสิ่งที่น่าจะผิด
3. **มีทั้งสองฝั่งแต่ยอดหรือวันที่ต่าง** — บอกส่วนต่าง

ถ้ายอดคงเหลือตรงกันและไม่มีกลุ่ม 1-3 ให้บอกสั้น ๆ ว่าบัญชีนี้ตรงแล้ว

### 4. ตรวจก่อนสรุปภาษี
เรียก `tax_report` ของกิจการ+เดือนนั้น แล้วแจ้งก่อนเสมอถ้า:
- `purchases_with_vat_but_no_invoice_no` ไม่ว่าง — บิลซื้อที่มี VAT แต่ยังไม่กรอกเลขใบกำกับ (ระบบยังนับเป็นภาษีซื้อ แต่ควรกรอกเลขก่อนยื่น)
- ยังมีบิลจากขั้นที่ 3 ที่ยังไม่ได้ลง/แก้ — ตัวเลขภาษียังไม่ใช่ตัวสุดท้าย
- `filed: true` อยู่แล้ว — เดือนนี้ผู้ใช้กดยื่นไปแล้ว ถ้าตัวเลขเปลี่ยนต้องยื่นเพิ่มเติม

### 5. ตารางกรอก ภพ.30 (เฉพาะกิจการที่จด VAT)
เรียงตามช่องของแบบ ภ.พ.30 (ตรวจกับหน้าจอ e-Filing จริงทุกครั้ง — ถ้าลำดับ/ชื่อช่องไม่ตรง ให้ยึดหน้าจอจริง):

| ช่อง | ความหมาย | ค่าจาก `tax_report.pp30` |
|---|---|---|
| 1 | ยอดขายในเดือนนี้ | `sales_amount` |
| 2 | หัก ยอดขายที่เสียภาษีอัตรา 0% | 0 (ระบบไม่แยก — ถามผู้ใช้ถ้ามีส่งออก) |
| 3 | หัก ยอดขายที่ได้รับยกเว้น | 0 (ระบบไม่แยก) |
| 4 | ยอดขายที่ต้องเสียภาษี | ช่อง 1 − 2 − 3 |
| 5 | ภาษีขายเดือนนี้ | `output_vat` |
| 6 | ยอดซื้อที่มีสิทธินำภาษีซื้อมาหัก | `purchase_amount` |
| 7 | ภาษีซื้อเดือนนี้ | `input_vat` |
| 8 / 9 | ภาษีที่ต้องชำระ / ชำระเกิน เดือนนี้ | ช่อง 5 − 7 (บวก = 8 · ลบ = 9) |
| 10 | ภาษีชำระเกินยกมา | `vat_carried_in` |
| 11 | ภาษีสุทธิที่ต้องชำระ | `vat_payable` |
| 12 | ภาษีสุทธิที่ชำระเกิน (ยกไป) | `vat_carry_forward` |

- ช่อง 4 และ 8/9 เป็นการลบเลขในตาราง ไม่ใช่การคำนวณภาษีใหม่ — ถ้าผลไม่สอดคล้องกับ `vat_payable`/`vat_carry_forward` ให้บอกผู้ใช้ ห้ามแก้ตัวเลข
- แสดงทศนิยม 2 ตำแหน่ง มีคอมมาคั่นหลักพัน

### 6. ภงด.3 / ภงด.53
แสดงจาก `tax_report.pnd3` และ `pnd53`: จำนวนราย · ยอดเงินได้ที่จ่าย (`paid`) · ภาษีที่หัก (`wht`) · รายชื่อ (ชื่อ, เลขผู้เสียภาษี, ยอด, ภาษี) — ถ้าเดือนนั้นไม่มีการหักเลย บอกว่าไม่ต้องยื่น

### 7. ปิดท้าย
- เตือนผู้ใช้ไปกด **ยื่นแล้ว** และ **บันทึกจ่าย** ในแอป ที่ บัญชี → เอกสารสรรพากร (ไม่งั้นระบบจะเตือนกำหนดยื่นต่อทาง LINE)
- สรุปสิ่งที่ยังค้าง (บิลที่ต้องไปแก้เอง · เลขใบกำกับที่ยังไม่ได้กรอก) เป็นรายการสั้น ๆ
